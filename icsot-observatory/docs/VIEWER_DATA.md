# Local viewer data contract

`icsot_observer.viewer_data.ViewerData(workspace, roots=None, *, private_key_path=None, offline=False)` is a read-only adapter. The workspace is the project directory containing `public_patch_corpus_185.csv`; the package directory is normalized to its parent. Explicit local roots must contain `runs/<numeric-repository-id>/*.manifest.json` and the matching content-addressed `objects/sha256/` tree. Default discovery uses existing evidence roots below the workspace. No collection or GitHub write is invoked.

The adapter exposes:

| Method | Result |
| --- | --- |
| `overview(refresh=False)` / `list_repositories(refresh=False)` | `repos` / `repositories`, `stats`, `gaps`, `metadata_status`, qualification |
| `repo(repo_key)` / `list_captures(repo_key)` | `repo` / `repository`, `captures`, `attempts`, `categories`, `gaps` |
| `compare(repo_key, left_key, right_key, category=None, offset=0, limit=100)` | Paged `items`, `total`, coverage, per-category `change_breakdown`, Git ref OID changes |
| `entity_detail(repo_key, capture_key, kind, entity_id)` | Observed entity or explicit not-observed/unknown state, raw response references |
| `raw_record(repo_key, capture_key, ref_key)` | Manifest or response envelope and bounded raw-text preview with original SHA-256 |
| `load(repo_key, capture_key)` / `load_capture(...)` | Explicit selected-capture load result, progress and disk-budget status |
| `git_diff(repo_key, capture_key, base_oid, head_oid, path=None)` | Explicit offline full-bundle restore/fsck, bounded changed-file list, commit metadata and patch |
| `budget_status()` | Current shared local-disk accounting |

Repository and capture keys are opaque registered identifiers. Raw references are `manifest` or `response-<number>` within the selected manifest. There is no filesystem-path endpoint. Every local manifest and response body is hash checked when read; evidence symlinks and escaping paths are rejected. A capture belongs to one bound numeric repository identity. Inventory/index/manifest identities, release bindings and source cohort hashes must agree.

Categories are `issues`, `pulls`, `comments`, `releases`, `tags`, `events`, `git_refs` and `raw_records`. `coverage` returns the six API category summaries. Comparing a capture with itself lists its observed entities. A changed complete JSON representation can reflect counts or other metadata; `changed_fields` identifies the changed top-level fields. Missing records are `not_observed_left` / `not_observed_right`. They are never interpreted as deletion or historical absence. Events remain opportunistic, and deltas remain overlapping query results rather than full snapshots. An uncollected or unavailable category has an unknown count (`null`), distinct from an explicitly captured empty listing.

Checkpoint attempt IDs and qualified legacy query-start boundaries select accepted traversal pages. Validation/recheck pages and abandoned attempt pages remain available as raw records. Retried legacy traversals without an accepted boundary are not mixed into an entity projection. Malformed UTF-8/JSON produces a visible projection gap; raw display explicitly labels replacement decoding while retaining the original-byte hash.

Capture metadata distinguishes `complete`, `partial`, `coverage_unknown`, lane, mode, UTC collection interval, independent API/Git-ref intervals, source lineage, timestamp statements and load state. OpenTimestamps/RFC 3161 statuses are archived verifier statements: this viewer performs no independent timestamp verification. When public proof history exists, its current record is fetched from a pinned `collector-attestations` commit; unavailable maintenance state remains explicit.

GitHub discovery uses existing `gh` authentication and GET requests only. Public release/asset metadata, inventories and catalogs are cached in memory with cumulative session limits of 10,000,000 bytes, 200 HTTP requests and five catalog attempts. Per-repository indexes are read lazily. Failed or incomplete attempts remain in `attempts`; absent index/payload coverage is not promoted to success. Metadata browsing works without a private key or encrypted payload download.

A transient catalog or index error is an unavailable/partial discovery state, never a completed empty catalog. `metadata_status` reports the last error, attempts, quota reset/retry time, request/byte budgets and whether an explicit retry is allowed. The dedicated quota endpoint is checked before core catalog requests. Normal reads do not repeatedly retry a failure. An explicit Refresh retries after the backoff/reset while preserving verified loaded captures and immutable cached metadata; mutable listings are refreshed and exact duplicate attempt rows are suppressed. Repository `capture_count` remains the number of registered captures, while `capture_count_known=false` and `remote_discovery.availability_known=false` distinguish an incomplete remote inventory from a known count. Offline mode also leaves remote availability unknown.

Loading encrypted evidence requires an explicit selected capture and a server-local private-key path. Key contents and the configured key path are never returned by adapter methods. Native multipart indexes and historical encryption-migration mappings preserve ordered plaintext/ciphertext identities. `LocalBudget` always uses `<project>/analysis/local-data-budget` and counts the whole project plus registered roots against 2,000,000,000 bytes. Each ciphertext part is reserved before download, authenticated and replayed into a bounded XZ/TAR stream; plaintext archives are never staged. Only one ciphertext part is held at once. Provisional JSON projections become visible only after the entire archive scan verifies. Retained raw-byte limits are 16 MiB per member, 64 MiB per selected archive and 128 MiB per viewer session; parsed JSON maps and Python overhead require additional memory. Omitted members produce explicit gaps.

API responses use bounded previews and pagination. Original raw response bytes remain identified by SHA-256; displayed JSON/body/diff text may be an excerpt. Loading a later native export does not automatically fetch its prerequisites. A manifest already delivered in a previous export is identified by the immutable index basename and marked as a prerequisite. Authenticated dependency manifests are retained within the session memory bound; missing manifests/CAS objects remain explicit gaps until the relevant earlier capture is separately selected.

Git file diffs require an explicit operation. A self-contained full bundle must be at most 32 MiB and declare no more than 100,000 pack objects. Local CAS bytes are hash-checked into an owned bounded snapshot; remote bundles are extracted only after the complete encrypted archive verifies and are held in a managed cache capped at 64 MiB. Cache reads hold an eviction lease. Ciphertext stages are released before a fixed 256 MiB native volume is created. The shared budget reserves both the image and mounted allocation. Git initializes an isolated bare repository, verifies/fetches the full bundle, runs `fsck`, verifies captured refs, and compares captured OIDs that resolve to retained commits. There is no network, hooks, external diff or textconv. A browser-provided file selection must match an actual changed Git-tree path and uses a literal pathspec. The response limits file lists to 500 and patch output to 512,000 bytes; larger or unavailable preparations remain explicit. Commit author/committer names and times are source assertions. Incremental bundles requiring external objects and large graphs are not restored by this viewer.

`tests/test_viewer_data.py` uses only labeled synthetic fixtures, including authenticated encrypted archives. It does not fabricate study observations or download the corpus.
